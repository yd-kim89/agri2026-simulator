0. 범위

운영자(사장님) 확정값으로 standards 시드를 조정하고, 참고용 라벨 문안을 교체한다. 스키마·엔드포인트·검증 로직 무변경. 롤백은 역-UPDATE.

먼저: marketplace.db 백업(cp marketplace.db marketplace.db.bak.$(date +%Y%m%d_%H%M)). 값 변경이지만 백업 우선.

1. 표준표(standards) 값 조정

필드현재 시드변경
등급 grade특 · 상 · 보통유지 (농관원 표준규격 등급규격 그대로)
규격 spec상 · 중 · 하특대 · 대 · 중 · 소 (등급과 축 중복 해소 → 크기 축으로 분리)
수량 단위 qty_unitkg · 상자 · 망 · 포 · 박스kg · 상자 · 망 · 단 · 포 (상자=박스 중복 제거, '단' 추가)

단위 의미: 망=양파·마늘·감자 / 단=대파·시금치 묶음 / 포=마늘·양파 대량 / 상자=청과 표준 상자(품목별 kg 병기 권장).

standards 실제 컬럼 구조에 맞춰 위 값으로 UPDATE(값 리스트가 행/CSV 어느 형태든 spec·qty_unit 항목만 교체, grade 무변경). 자유입력 400·표준표 강제 로직은 그대로 두고 허용 값 집합만 갱신.

품목별 override는 이번 범위 밖: 우선 공통 기본값만 확정. 품목별 차등(예: 대파='단' 강조, 사과·배='상자(10kg)')은 확장 시 standards에 품목 행 추가로 별도 진행.

변경 전: ※ 본 초안은 예측·시세 데이터 기반 참고용입니다. 최종 조건은 당사자가 확정합니다.

가격 밴드가 null(신뢰도 낮음)일 때, 밴드 자리에 "예측 밴드 미제공 — 최근 실측 시세만 참고" 문구가 노출되는지 확인하고, 없으면 추가한다(과장·환각 방지 일관).

3. AI 산문 정책 (확인·유지)

  • RFQ·입찰·거래 확인서는 템플릿 생성 유지 — 법적 성격 문서라 결정적·환각 없는 템플릿이 LLM 산문보다 안전(의도된 설계).
  • .env에 ANTHROPIC/OPENAI 키 미등록 상태는 거래 문서 품질엔 영향 없음(가격 밴드는 예측 API 소관). LLM 키는 Phase 6 RAG 착수 시 등록. 이번 지시서에서 키 추가·LLM 전환은 하지 않는다.

4. 재검증 (완료 조건 · DB/응답 증거)

  1. standards 조회 → spec=특대·대·중·소, qty_unit=kg·상자·망·단·포, grade=특·상·보통 확인.
  2. 표준표 강제 회귀: 자유입력(예: spec="특상") 여전히 400, 허용값(대/단 등)은 통과.
  3. RFQ 초안 1건 생성 → 새 참고용 라벨 문안 노출 확인.
  4. 신뢰도 낮음 품목(예: 양파) 밴드 null → "예측 밴드 미제공" 문구 노출. 양호 품목(대파)은 밴드 표시(회귀 무결).
  5. 기존 §5 22/22 회귀 무결(값 변경이 왕복·권한·만료 로직에 영향 없음).

5. 롤백

표준표는 역-UPDATE(백업 marketplace.db.bak.* 재적용 또는 이전 값으로 UPDATE), 라벨 문안은 이전 문구로 복원. 스키마·라우트 무변경이라 영향 0.
