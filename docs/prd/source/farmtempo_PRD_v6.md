## 02. 어떤 분야에 AI를 도입하려고 하는가

(v5 원문 유지 — 전국 약 5만 개 독립 소형 마트의 농산물 매입 의사결정 업무. 데이터 활용 성숙도 4단계 사다리에서 3단계(시뮬레이션)를 담당하며 1·2단계(자동화·예측)는 라이브. 이중 페르소나(사람+AI) 설계 대전제, 양면 네트워크의 씨앗 대전제 포함.)

**v6 보강 — 양면 네트워크의 씨앗 → 나무:** v5까지 "시뮬레이션 의향 데이터의 익명 집계 → 공급 측 수요 신호"가 씨앗이었다면, v6는 이를 **RFQ(구매 요청) 역경매 입찰 → AI 매칭 → 거래 장부**로 발아시킨다(15절). 시뮬레이션이 "언제 살까"에 답하고, 마켓플레이스가 "누구에게 살까"에 답하며, 거래 데이터가 다시 시뮬레이션·매칭 AI를 강화하는 순환 구조가 v6의 골격이다.

## 03. 현재 어떤 문제가 있는가

(v5 원문 유지 — 고통 5항목(믿을 시세 부재·명절 급등 사후 체감·반직관 패턴·시뮬레이션 공백·공급 측 거울상 문제), 기존 대안의 한계 4항목, 경쟁 구도 분석 표(KAMIS/농넷·팜에어한경 테란·마켓보로 식봄/마켓봄·도매상 전화·엑셀 수기), 문제의 규모 국가 통계(유통비용률 49.2%, 직거래 16.7%, 최대 32.5%p 마진 격차), 정부 정책 정합(6,000억 유통구조 개선 + 2026-07-14 대통령 "유통 구조 근본 개혁" 발언) 전부 준용.)

**v6 보강 — 경쟁 구도에서의 위치 이동:** v5의 결론은 "조회·예측·거래 사이의 **의사결정 계층** 공백에서 시작해, 결정 데이터를 축적한 뒤 직거래 매칭으로 확장한다"였다. v6는 그 확장을 실행 범위로 옮긴다. 이때 경쟁 지형이 한 칸 넓어진다:

| 신규 비교 대상 | 구조 | 우리의 차별화 |
|-|-|-|
| **마켓보로 식봄** (오픈마켓) | **판매자가 정한 가격**을 수요자가 고르는 정가 오픈마켓 | 우리는 **수요자가 조건(수량·규격·등급·납기)을 게시하고 농가가 입찰**하는 역경매(RFQ). 가격 결정권의 방향이 반대 |
| **농식품부 온라인도매시장** (공공) | 도매법인·시장도매인 중심의 B2B 거래소. 국가가 직거래·유통단계 축소를 직접 유도 | 경쟁이 아니라 **그 위의 의사결정·매칭 계층** — 우리 사용자는 온라인도매시장 가격도 비교 기준으로 활용. 소형마트·급식이라는 라스트마일 수요자와 소규모 농가는 공공 거래소가 잘 못 닿는 구간 |
| **전화 영업 (농가 측 대체재)** | 농가가 마트에 개별 전화 | RFQ가 "확정 수요 리드"를 농가에 배달 — 영업을 응답으로 바꾼다 |

**정직한 리스크 표기(v6 추가):** ① 공공 온라인도매시장이 소형 수요자·소농으로 저변을 확대할 가능성 — 대응: 공공 거래소는 표준 거래 인프라이고, 우리는 예측·시뮬레이션·회계까지 잇는 의사결정 계층 + AI 매칭이라는 별개 층위. 필요 시 연동(가격 참조·판로 병행)으로 보완재화 ② 역경매 모델은 농산물 품질 불확실성 탓에 실패 사례가 있는 구조 — 대응: 15.4 선결 과제(등급·규격 표준화, 현품 사진 판독, 분쟁 중재)를 입찰 기능과 같은 우선순위로 구현.

### P1.7 — 직거래 RFQ 마켓플레이스 (v6 신규 승격) ⭐

> **위치:** 상세 전략·단계·선결 과제는 **15절**. v5까지 Non-Goal이던 "거래 마켓플레이스" 중 **입찰·매칭·거래 데이터 계층**을 정식 범위로 승격한다. 물류·에스크로는 계속 제외(아래 Non-Goal).

- **농가 상점(홍보):** 농가가 프로필·품목·출하 일정·인증(농업경영체 등록번호 검증)을 등록하고 수요자에게 노출. S-003 농가 디렉토리의 승격형.
- **RFQ 역경매 입찰:** 마트·외식업체가 품목·수량·규격·등급·납기·희망가 밴드를 게시 → 조건 적합 농가에 자동 알림 → 농가는 가격·가용 물량만 입력해 입찰 → 수요자에게 비교표 제공.
- **AI 매칭·제안서:** 시세·예측·이벤트 계수를 근거로 적정가 밴드 제시, 농가 입찰 제안서·수요자 RFQ 초안 자동 작성, 매칭 스코어 산출. 외부 AI 에이전트가 RFQ 게시·입찰 조회를 API로 호출 가능(B2AI).
- **거래 장부·회계 분석:** 낙찰~납품 기록을 계정 귀속 장부화(S-002 확장), 현품 사진(S-006) 삼중 대조, **의제매입세액공제 자동 계산·증빙 리포트**(수요자 측)·수취가 리포트(농가 측).

- **최적 발주량 자동 산출 (4단계 최적화):** 시뮬레이션 데이터 축적 후 차기 단계. (유지)

## 06. 사용자 시나리오

(v5 원문 유지 — ① 대표 시나리오(배추 이중 절감) ② 명절 선매입 ③ 반직관 억제 ④ 공급 측 수요 신호 ⑤ AI 사용자 ⑥ v4 통합 ⑦ v5 결제 통합. ④는 v6에서 ⑧로 자연 연결된다.)

**⑧ (v6 마켓플레이스 통합 — RFQ 게시부터 회계 리포트까지):**

- **[RFQ 게시 — 수요자]** 급식업체 구매 담당 박OO이 시뮬레이터에서 "양파 400kg, 다음 주 화요일 납품"의 3-시나리오를 확인한 뒤, 결과 화면의 "직거래 입찰 받기" 버튼을 누른다. AI가 시뮬레이션 조건 + 예측가를 바탕으로 RFQ 초안(품목·수량·규격 상·등급·납기·희망가 밴드 1,100~1,300원/kg — 예측 도매가 대비 근거 표기)을 자동 작성. 박OO은 검토 후 게시.
- **[입찰 — 농가]** 조건 적합(품목×권역×출하 가능 시점) 파트너 농가 6곳에 알림. 최농가는 AI가 제안한 적정가 밴드를 참고해 1,180원/kg·400kg 가용으로 입찰 — 입력은 2개 필드뿐. AI가 최농가의 등록 정보·과거 거래 이력으로 입찰 제안서(농가 소개·품질 근거·납품 조건)를 자동 첨부.
- **[비교·낙찰 — AI 매칭]** 박OO 화면에 입찰 3건 비교표(단가·총액·도매가 대비 절감률·매칭 스코어·거래 이력·인증 상태). AI 추천 근거 표기("최농가: 단가 2위이나 동일 권역 배송·직전 거래 무분쟁으로 종합 1위"). 박OO이 낙찰 확정 → 양측에 거래 확인서(품목·수량·단가·납기) 자동 발행.
- **[납품·기록]** 납품일 현품 사진 촬영 판독(S-006) → 거래 확인서와 삼중 대조 → 거래 장부(S-002 확장)에 확정 기록. 대금은 당사자 간 지급, 계산서 발행 여부만 기록.
- **[회계 — 월말]** 박OO: "이번 달 직거래 매입 320만원, 도매 대비 절감 41만원, **의제매입세액공제 예상액 16.4만원**(증빙 목록 첨부)" 리포트. 최농가: "도매 출하 대비 수취가 +12%, 이번 달 낙찰 3건" 리포트 — 양측 모두 다음 달에도 돌아올 숫자를 받는다.

> ⑧은 시뮬레이션(언제)→매칭(누구에게)→장부·회계(얼마나 남았나)의 전체 루프를 완성하며, ⑤(AI 사용자)와 결합해 외부 AI 에이전트가 RFQ 게시→입찰 조회→낙찰 제안까지 API로 수행하는 B2AI 시나리오로 확장된다(human-in-the-loop 승인 필수).

## 15. 직거래 마켓플레이스 — 4단계 승격 전략 (v6 신규) ⭐

> **한 문장 요약:** 국가가 예산과 대통령 지시로도 못 만든 직거래의 라스트마일을, 시뮬레이션 데이터 위의 **RFQ 역경매 + AI 매칭 + 거래 장부**로 민간이 먼저 완성한다.

### 15.1 배경 — 국가가 유도하는 직거래, 비어 있는 실행 계층

- **[확인 사실]** 정부는 농산물 유통구조 개선에 약 6,000억 원을 투입하고(2025.9 관계부처 합동), 대통령이 2026.7 국무회의에서 유통구조 근본 개혁을 재차 지시했다(03절 출처). 유통비용률 49.2% vs 직거래 경로 16.7% — **최대 32.5%p의 격차가 국가 통계로 확인된 상태에서, 직거래로 옮겨 가는 실행 도구가 없다.**
- **[본인 판단]** 공공의 답(온라인도매시장)은 도매법인 중심의 거래 표준화다. 소형 마트·급식의 "다음 주 화요일 양파 400kg"과 소규모 농가의 "이번 주 출하 물량"을 잇는 매칭은 공공 거래소의 구조상 공백이며, 이 공백이 farmtempo의 승격 지점이다. 국가 정책과 경쟁하지 않고 같은 방향의 실행 계층을 맡는다는 v5의 포지션은 그대로다.
- **차별화의 핵:** 식봄(판매자 정가 오픈마켓)과 반대 방향인 **수요자 주도 역경매(RFQ)**, 그리고 그 위의 **AI 제안서·매칭**. 조회→예측→시뮬레이션→매칭→장부·회계가 한 플랫폼에서 순환하는 구조는 현재 시장에 없다(03절 v6 보강 표).

### 15.2 4단계 구조 (사용자 아이디어의 확정 반영)

**1단계 — 양면 유입 (농가 등록 × 수요자 유입):**

- **원칙 — 전국 커버리지는 결과이지 전략이 아니다.** "국내 등록 농가 전부"는 지향점이되, 97.4만 농가의 자발 등록은 일어나지 않고 농업경영체 등록정보는 개인정보라 이관 불가 [확인 사실]. 실행 전략은 **권역×품목 밀도**: 경기 북부×양념류(양파·대파·마늘 — 검증 품목 1순위와 동일)에서 "RFQ를 올리면 24시간 내 입찰 3건"이 성립하는 최소 유동성을 먼저 만든다.
- **Buyer-first 순서:** 베타 마트·급식 20개소(수요)가 먼저다. 이들의 시뮬레이션·RFQ가 만드는 **확정 수요 리드**를 들고 농가를 영업한다 — 농가에게 첫 화면은 "가입하세요"가 아니라 "당신 품목을 사려는 RFQ가 N건 있습니다"여야 한다.
- **농가 온보딩:** 농업경영체 등록번호 검증(결과 boolean만 저장 — 08.7), 상점 프로필(상호·시군구·품목·출하 일정), 기존 `농가등록_신청심사_명세`·`품질보증_농가관리_설계안` 문서의 심사·품질 체계를 이 단계의 입점 기준으로 재활용한다.

**2단계 — 홍보 × RFQ 역경매 입찰:**

- **농가 → 수요자 (홍보):** 농가 상점이 디렉토리(S-003 승격)에 노출. 출하 예정 물량을 "판매 제안"으로 게시 가능(정방향 채널).
- **수요자 → 농가 (역경매, 핵심):** 마트·외식업체가 품목·수량·규격·등급·납기·희망가 밴드를 게시(RFQ) → 조건 적합 농가 자동 알림 → **입찰은 단가·가용 물량 2필드**(농가의 디지털 부담 최소화가 공급 측 활성화의 전제) → 비교표 → 낙찰 → 거래 확인서 자동 발행.
- **가격 발견:** 입찰가·낙찰가는 익명 집계되어 "직거래 실거래 시세"라는 신규 데이터 자산이 된다(09절 v6).

**3단계 — AI 분석 · 제안서 · 매칭:**

- **적정가 밴드:** 시세·예측(1,884개 모델)·이벤트 계수를 근거로 RFQ 희망가와 입찰가 양쪽에 적정 밴드 제시 — 수요자는 바가지를, 농가는 헐값 낙찰을 피한다. 신뢰도 5등급·"참고용" 라벨 원칙 그대로 적용.
- **문서 자동 작성:** 수요자 RFQ 초안(시뮬레이션 조건에서 자동 생성), 농가 입찰 제안서(등록 정보·거래 이력·품질 근거로 자동 작성) — 양측 모두 "쓰는 부담"을 AI가 흡수한다.
- **양방향 문서 교환 (v6.1, 숨고 패턴):** AI가 만든 문서는 작성자 편의가 아니라 **상대방이 받아보는 산출물**이다. 수요자는 농가별 **입찰 제안서**(상점 소개·품질 근거·납품 조건·AI 추천 근거)를 받고, 농가는 RFQ 열람 시 **AI 분석 요약**(적정가 밴드·최근 시세 추이·이벤트 신호·내 조건 적합도)을 받는다. 즉 요청→분석→문서→수신의 왕복이 양쪽 모두에서 성립하며, 모든 AI 문서에는 근거·신뢰도 등급·"참고용" 라벨이 동반된다.
- **매칭 스코어:** 가격 + 거리(권역) + 거래 이력(무분쟁·납기 준수) + 품질(현품 사진 판독 이력) 종합. **추천 근거를 자연어로 항상 표기**(블랙박스 추천 금지 — AI 가드레일 원칙).
- **B2AI:** RFQ 게시·입찰 조회·낙찰 제안 전 과정을 OpenAPI + MCP 도구로 노출. 외부 기업 AI가 "다음 주 식자재 발주"를 수행할 때 farmtempo가 매칭 인프라로 호출된다 — 프로젝트 핵심 비전("AI가 활용하는 AI 플랫폼")의 실체. 자동 낙찰은 금지, 사람 승인 필수(human-in-the-loop).

**4단계 — 거래 데이터 축적 · 투명성 · 회계 분석:**

- **거래 장부:** 낙찰→납품→현품 사진 삼중 대조→확정 기록(S-002 확장). 거래 확인서 스냅샷으로 "말이 바뀌는" 분쟁을 구조적으로 차단 — 이것이 거래 투명성의 실체다.
- **회계 분석 (수요자 측 킬러 기능):** 농산물은 부가세 면세 → 마트·외식업체는 **의제매입세액공제** 대상인데 수기 증빙 관리가 취약하다. 플랫폼 거래 기록에서 공제 예상액·증빙 목록을 자동 생성 — 구독을 끊으면 세무 편익이 사라지는 락인 장치. **단, 계산은 "참고용 — 세무사 확인 권장" 라벨 강제, 세무 대리 행위로 오인될 표현 금지 [전문가 검토 필요].**
- **농가 측:** 수취가 리포트("도매 출하 대비 +N%") — 농가가 매달 돌아올 이유.
- **플라이휠:** 거래 데이터 → 매칭 정확도·적정가 밴드 개선 → 성사율 상승 → 데이터 증가. 시뮬레이션(의향)과 장부(실거래)가 예측 모델의 사후 검증 데이터로도 환류된다.

### 15.3 콜드스타트 해소 순서 (경험적 이득 우선 원칙의 확장)

1. 수요 측: 기존 베타 20개소가 시뮬레이터 결과에서 원클릭 RFQ (전환 마찰 최소 — 이미 있는 사용자 흐름에 버튼 하나)
2. 공급 측: RFQ 리드를 들고 권역×품목 타깃 농가 직접 영업 (첫 제안: 무료 + "입찰만 하면 됨")
3. 최소 유동성 달성(RFQ당 입찰 ≥ 3) → 인접 권역·품목 복제
4. 성사 사례("도매 대비 -N%, 농가 수취 +M%")를 양측 영업 자료로 순환

### 15.5 리스크와 방어 (정직 표기)

- **유동성 실패(최대 리스크):** RFQ에 입찰이 안 붙으면 한 번의 나쁜 경험으로 수요자가 이탈 → 방어: 권역×품목 집중, "평균 응답 시간" 정직 표기, 입찰 부족 시 기존 직납 견적(P1) 경로로 자동 폴백.
- **수수료 회피(장외 거래):** 첫 거래 후 직접 연락으로 이탈 → 방어: 수수료를 낮게(2~3%), 플랫폼에 남아야만 생기는 가치(장부·회계 리포트·공제 증빙·분쟁 보호)를 거래 자체보다 크게 설계. 4단계(회계)가 곧 이탈 방지 장치다.
- **공공·대형 플레이어 진입:** 온라인도매시장 저변 확대, 마켓보로 AI 예고 → 방어: 27년 실측 계수·특허·신뢰도 체계 + 의사결정~회계 풀루프 + B2AI 선점(03절 v6).
- **1인 팀 실행 부하:** Phase 9는 5~15분 Task 분해·위임 프로토콜로만 진행, 베타 온보딩(수요 밀도) 미달 시 Phase 9c 착수 보류.

### 15.6 수익 모델 정합

구독(SaaS, 14절 빌링으로 회수) + 낙찰 수수료 2~3%(농가 초기 무료 원칙 유지, 성사 시 과금) + 회계 리포트(상위 플랜 번들) + B2AI API 호출 과금(RFQ·입찰·직거래 시세 지수). 11절 v6 KPI로 측정.

### 15.7 UX 벤치마크 — 숨고(Soomgo) (v6.1 추가)

> 숨고는 "요청서 게시 → 조건 적합 전문가(고수)에게 전달 → 견적서 발송 → 비교·선택 → 플랫폼 내 채팅"으로 국내 역경매 매칭 UX의 사실상 표준을 만들었다. 구조는 차용하되, 수익 구조는 의도적으로 다르게 간다.
